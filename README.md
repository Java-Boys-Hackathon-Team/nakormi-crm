### Локальный запуск

На машине разработчика проект самодостаточен: поднимает собственные PostgreSQL,
MinIO и pgadmin, ничего внешнего ему не нужно.

- Клонируйте репозиторий с GitHub

- Скачайте и установите JDK 17 для своей ОС на сайте Eclipse [по этой ссылке](https://adoptium.net/temurin/releases/)

- Создайте `.env` рядом с `docker-compose.yml` по образцу `.env.example`. Без него
  приложение не стартует: токен телеграм-бота читается из окружения, и при его
  отсутствии контейнер уходит в перезапуск с ошибкой про неразрешённый placeholder.
  Для локальной работы годятся любые значения-заглушки.

- Выполните команду сборки:

```shell
# linux or mac os
./gradlew -Pvaadin.productionMode=true bootJar

# windows 
gradlew.bat -Pvaadin.productionMode=true bootJar
```

- Установите Docker Desktop с [официального сайта](https://www.docker.com/products/docker-desktop/)

- Запустите все контейнеры:
```shell
docker compose up -d
```

- Чтобы войти в систему "Накорми CRM" перейдите по ссылке [http://localhost:8080](http://localhost:8080). Логин: "super_admin", пароль: "admin".

### Продовое окружение

На сервере проект **не поднимает свои базу и хранилище**. Они живут отдельно, в
[common-infra](https://github.com/Java-Boys-Hackathon-Team/common-infra) - общем
наборе инфраструктурных сервисов, к которым подключены все проекты сервера. Это
экономит память: один PostgreSQL и один MinIO вместо копии на каждый проект.

Поэтому запусков два, и они независимы:

| Файл | Где используется | Что поднимает |
|---|---|---|
| `docker-compose.yml` | машина разработчика | приложение и весь его стек |
| `docker-compose.prod.yml` | сервер | только приложение, подключённое к сети `common-infra` |

Прод-файл не наследует локальный и ничего в нём не отключает - это два разных
способа запуска, чтобы правка одного никогда не ломала другой.

Параметры подключения (адрес базы, имя, пароль, бакет) лежат на сервере в
`.env.prod` рядом с прод-файлом, права `600`, в репозиторий не коммитятся.
Заводятся они на стороне общей инфраструктуры:

```shell
cd ~/common-infra && ./scripts/add-project.sh nakormi --bucket nakormi
```

Скрипт создаёт базу с отдельным пользователем и бакет, после чего печатает
готовый набор переменных для `.env.prod`.

### Развёртывание

Разворачивает GitHub Actions: **Actions → CI/CD Pipeline for Nakormi Project →
Run workflow** с указанием ветки. Workflow собирает проект, заходит на сервер по
ssh и запускает `deploy.sh`, который пересобирает jar и поднимает приложение
прод-файлом. Перед работой скрипт проверяет, что на месте `.env.prod` и сеть
`common-infra`, - иначе останавливается с понятным сообщением, а не посреди
развёртывания.

Сборка на сервере идёт на JDK 17: версия по умолчанию там новее, и без явного
выбора сборка падает.
